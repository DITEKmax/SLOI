# SLOI 1.0.0-rc1 — установка и работа

## 1. Что потребуется

Windows 10/11 x64, NVIDIA GPU с актуальным драйвером, доступная пользователю папка, интернет на время первой установки. Цель проекта — RTX 3050 Ti Laptop 4 GB, Ryzen 9 5900HX, 16 GB RAM; это целевая конфигурация, **не результат выполненного здесь аппаратного теста**.

Предварительно отведите примерно **25–30 GiB** под модели, PyTorch/CUDA, изолированные окружения и установочные кэши. Это запас для планирования, а не измеренный итоговый размер Windows-установки. После установки фактические размеры весов записываются в отчёт. Многогигабайтные исходные видео не копируются в проект.

NVIDIA-драйвер установщик не меняет. Полный CUDA Toolkit вручную не требуется по выбранной схеме: CUDA-библиотеки берутся из проектного PyTorch CUDA-окружения. Реальная совместимость DLL всё равно проверяется smoke-тестом. При отсутствии системного Microsoft VC++ Runtime загрузка некоторых бинарных модулей Windows может не пройти; это будет ошибкой диагностики, а не скрытым переходом на CPU.

## 2. Распаковка

Распакуйте ZIP целиком. Получится, например:

```
D:\SLOI\
    install.bat
    start.bat
    diagnose.bat
    benchmark.bat
    update.bat
    sloi\
    frontend\dist\
    config\
```

Нужна обычная доступная для записи папка. Не используйте `Program Files`, временную папку внутри архиватора или синхронизируемую облаком директорию. Короткий путь вроде `D:\SLOI` уменьшает риск ограничений длины путей Windows. Запуск от администратора для самой установки проекта не нужен.

Не переносите готовую установленную папку произвольно после создания Python venv: окружения могут содержать абсолютные пути. При переносе сохраняйте `models`, `data`, `config/app.yaml`, затем пересоздайте окружения через установку в новом месте.

## 3. Первая установка

Дважды нажмите **`install.bat`**.

Последовательность:

1. Проверка x64, драйвера NVIDIA и отсутствия активного экземпляра приложения.
2. Проверенная по SHA-256 загрузка uv, управляемого Python 3.13.5, создание core-окружения.
3. Установка изолированных окружений ONNX, Transformers/PyTorch CUDA и faster-whisper/CTranslate2. Одновременно модели в память не загружаются.
4. FFmpeg/FFprobe, четыре модели с закреплёнными Hugging Face commit SHA и Silero VAD. Проверяются размеры и доступные upstream SHA-256 файлов.
5. Загрузка Unbounded, Golos Text, Commissioner из Google Fonts и OFL-лицензий. FontTools проверяет наличие русской кириллицы и цифр. Шрифты затем обслуживаются локально, без обращения к Google при каждом открытии.
6. Настоящие локальные проверки: VAD, FFmpeg, загрузка каждой ASR на GPU, короткое распознавание, завершение worker, измерение VRAM после выгрузки.

Для короткой речи используются установленные Windows System.Speech голоса RU/EN. Отсутствие одного из голосов не доказывает несовместимость ASR: отчёт отдельно отмечает покрытие языков. Если голосов вообще нет, smoke-тест не может стать успешным по одному факту импорта библиотек.

### Итог установки

| Код | Значение |
|---:|---|
| 0 | Установка завершена, четыре коротких GPU-теста и проверки инструментов прошли |
| 2 | Среда установлена, но аппаратная проверка неполная, пропущена или выявила ошибку модели |
| 1 | Установка не завершилась; обычный запуск может быть недоступен |

**Код 0 не является оценкой точности, проверкой всей лекции или гарантией укладывания любого фрагмента в VRAM.**

Отчёты:

```
data\reports\install.json
data\reports\diagnostics.txt
data\reports\diagnostics.json
data\reports\lock-core.txt
data\reports\lock-onnx.txt
data\reports\lock-transformers.txt
data\reports\lock-whisper.txt
data\reports\fonts.json
runtime\bootstrap\bootstrap.log
```

`lock-*.txt` отражают фактически разрешённые на вашем компьютере версии всех пакетов. Основные зависимости закреплены в архиве; заранее проверенного Windows transitive lock в этой поставке нет.

При обрыве сети повторите `install.bat`: Hugging Face использует локальные загруженные файлы и механизм возобновления. Модели с корректными файлами не скачиваются заново без причины. Внешние URL/доступность сети могут изменяться; скрипт не обходит сетевые блокировки.

Если обычная загрузка файлов Hugging Face не продвигается, можно повторить установку из PowerShell с возобновляемыми проверенными HTTP-диапазонами: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install.ps1 -RangeDownloads`. Этот режим отключает Xet-транспорт только для текущего запуска и сохраняет проверку размера и SHA-256.

## 4. Ежедневный запуск

Откройте **`start.bat`**. Скрипт прочитает `runtime/active.json`, запустит локальный backend и откроет браузер:

```
http://127.0.0.1:8765
```

Повторный запуск той же установки открывает уже работающий экземпляр. Если порт принадлежит другой программе, получите понятную ошибку вместо второго backend.

**Консоль backend должна оставаться открытой.** Вкладку браузера можно закрывать: очередь продолжает работать. Закрытие консоли/`Ctrl+C`, завершение процесса или перезагрузка Windows останавливают распознавание.

Автозапуск в Windows и скрытая фоновая служба не устанавливаются. Загрузка ASR и шрифтов в обычном запуске выключена, модели читаются локально.

## 5. Добавление записей без копий

### Вариант A: «Добавить файлы»

Откроется системное окно Windows. Выберите один или несколько оригиналов. Программа запоминает разрешённые пути, не загружает содержимое в браузер и не создаёт `uploads/*.mp4`.

### Вариант B: «Windows drop»

Нажмите эту кнопку, затем перетащите файлы из Проводника в небольшое появившееся нативное окно. Это окно служит только приёмником путей; основной интерфейс остаётся в браузере.

### Вариант C: перетащить на веб-страницу

Ранее зарегистрированный файл может быть сопоставлен с известным оригиналом. Новый файл потребует выбора оригинала в системном окне. Это ограничение браузерного доступа к пути, а не стадия загрузки видео. При неоднозначном совпадении выбирайте файл явно.

Никаких браузерных расширений или массового поиска файлов по всему диску не устанавливается.

Видео не перезаписывается. При нескольких аудиодорожках выбирается дорожка по правилу probe, её индекс и предупреждение включаются в MD; остальные дорожки не смешиваются. Переключателя дорожек в UI v1 нет.

## 6. Очередь, модели, язык

Для каждого ожидающего задания выбираются модель и `AUTO / RU / EN`. Можно добавить несколько записей, изменить порядок и затем нажать запуск.

- GigaAM — русскоязычный вариант; EN для него недопустим.
- Qwen и Whisper — указанный язык передаётся runtime. Это не обещание идеального распознавания вставок другого языка.
- Parakeet — определяет язык сам; RU/EN записывается как пожелание, но не передаётся как несуществующий параметр декодера.
- Whisper здесь русский fine-tune, а не обычный OpenAI Turbo. Английский надо сравнить с Qwen/Parakeet на реальной записи.

Очередь идёт строго в заданном порядке. Между соседними файлами с одинаковой моделью worker переиспользуется. При смене модели старый процесс завершается. После простоя модель выгружается; базовый таймаут — 30 секунд.

**«Пауза после текущей»** сохраняет работу над активным файлом и запрещает начало следующего. **Отмена** прерывает активный файл с подтверждением; незавершённая расшифровка не выдаётся как готовая. После перезапуска backend активное на момент остановки задание становится прерванным; повторный запуск начинается с начала, готовое не теряется.

## 7. Результаты

```
<исходное-имя>__<модель>__<язык>__<дата-время>.md
```

Имя использует время запуска расшифровки и сохраняет кириллицу. Недопустимые Windows-символы заменяются, при совпадении добавляется суффикс. Программа не молча перезаписывает уже готовый файл.

- **Скачать MD** — стандартная загрузка браузера, в настроенную папку или с запросом места.
- **Скачать всё** — ZIP только из готовых MD.
- **Копировать** — текст без YAML.
- **Показать файл** — Проводник открывает внутренний результат в `data/results/<job-id>/`, а не неизвестное приложению место браузерной загрузки.

Готовые MD хранятся в проекте. Скачанный браузером MD — вторая маленькая текстовая копия; оригиналы аудио/видео не дублируются. Абсолютный путь исходника остаётся в локальной БД и не включается в Markdown.

## 8. Проверка GPU после установки

Быстрая диагностика без распознавания:

```
diagnose.bat
```

Повторить аппаратный smoke:

```
diagnose.bat --smoke
```

Использовать собственную короткую запись, например если Windows не имеет речевых голосов:

```
diagnose.bat --smoke --source "D:\Audio\sample.wav"
```

При этом берутся первые восемь секунд. Нужна реальная речь, не тишина. Полноценная языковая оценка этим не выполняется. Для smoke закройте backend; файлом блокировки исключён одновременный захват GPU приложением и тестом.

## 9. Полная лекция — benchmark

Закройте backend, затем выполните:

```
benchmark.bat "D:\Лекции\Лекция 07.mp4" --language ru
```

Скрипт последовательно запускает четыре модели с холодной загрузкой, считает полный SHA-256 исходника, сохраняет отдельный MD на каждый успешный прогон и сводку:

```
data\reports\benchmark-<run-id>.json
```

Результаты находятся в `data/results`; они также отражаются в БД и доступны после открытия приложения.

Для английской записи:

```
benchmark.bat "D:\IELTS\speaking.mp4" --language en
```

GigaAM в таком тесте пропускается. Для отдельной модели:

```
benchmark.bat "D:\Лекции\Лекция 07.mp4" --language ru --models qwen
```

Настройки первого прогона консервативные, batch=1. На реальном ноутбуке не подтверждены ни обещания скорости, ни оптимальный batch. Качество, пропуски и галлюцинации оцениваются по исходному звуку/эталону; WER/CER не выдумываются из текста модели.

## 10. Темы и настройки

В правом верхнем углу — Carbon / Paper / Signal и акцент. Они меняют шрифты, геометрию, графику и характер визуализации, а не только фон. Настройки сохраняются. Учитывается системное уменьшение движения; скрытая вкладка не продолжает декоративную анимацию.

Технические переопределения задаются в `config/app.yaml`. Файл изначально содержит только `schema: 1`; остальные значения берутся из `config/defaults.yaml`. После изменения технических настроек перезапустите backend. Путь модели должен оставаться внутри проекта.

## 11. Обновление

Сначала остановите backend. Сохраните новый архив рядом и запустите:

```
update.bat "D:\Загрузки\SLOI-next.zip"
```

Либо откройте `update.bat` и выберите ZIP в системном диалоге через «All files». Проверяются manifest и SHA-256 каждого файла; перед заменой создаются резервные копии кода, SQLite, пользовательского конфига и указателя окружений в `data/backups`.

Модели, готовые результаты, очередь, тема и `config/app.yaml` не удаляются. Новые зависимости устанавливаются в отдельные версионированные окружения. При ошибке установки восстанавливается предыдущий код/БД/конфиг/указатель окружений. Обновления не запускаются автоматически. Для обновления может понадобиться интернет.

Контрольные суммы обнаруживают повреждение/подмену относительно manifest, но не являются цифровой подписью издателя: устанавливайте только доверенные архивы.

## 12. Границы готовности

Облачный отчёт подтверждает логику и интерфейс, не Windows CUDA. Если GPU smoke сообщил ошибку, модель не считается принятой даже при наличии кнопки. Уменьшение batch/фрагмента может помочь только рабочим буферам, а не размеру весов. Программа не гарантирует 4 GB для каждого runtime и не скрывает такие ошибки.

Не посылайте в поддержку всю БД и записи без необходимости. Вначале достаточно `data/reports/diagnostics.txt` и `install.json`, предварительно просмотрев содержащиеся там пути/сведения о системе. Стандартные логи не предназначены для записи текста лекции.
