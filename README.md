# SLOI

SLOI локально распознаёт аудио и видео на компьютере с графическим процессором NVIDIA (GPU) и сохраняет результат в Markdown. Приложение не отправляет запись в облако и не пересказывает текст.

## Быстрый старт

1. Подготовьте Windows 10 или 11 x64, NVIDIA GPU с актуальным драйвером и доступную для записи папку.
2. Разместите проект, например, в `D:\SLOI` после клонирования или в `D:\SLOI-main` после распаковки ZIP. Замените путь и букву диска на свои, если нужно.
3. Откройте PowerShell, выберите путь установки и перейдите в корень проекта:

   ```powershell
   Set-Location D:\SLOI       # Git-копия
   # Для ZIP вместо предыдущей строки выполните:
   # Set-Location D:\SLOI-main
   ```

   **Внимание:** перед установкой или повторной установкой остановите локальную серверную часть (backend) через `Ctrl+C`. Установщик занимает блокировку каталога.

   ```powershell
   .\install.bat
   ```

4. Убедитесь, что установка вернула код 0. Код 2 означает, что установка готова, но GPU-проверка неполна.
5. Запустите приложение из того же каталога:

   ```powershell
   .\start.bat
   ```

6. Откройте `http://127.0.0.1:8765`. Выберите модель и язык, добавьте запись и нажмите **«Запустить очередь»**.

Оставьте окно запуска открытым до конца обработки. Backend — локальная серверная часть приложения. `Ctrl+C` останавливает её. Короткая проверка установки подтверждает запуск моделей, но не точность расшифровки.

## Установка

Планируйте 25–30 GiB (1 GiB = 1 073 741 824 байта) для проекта, моделей, окружений и установочных кэшей. Это запас для планирования, а не измеренный размер установки. Временные копии записей требуют дополнительного места.

При первой установке нужен интернет. Установщик подготовит проектные Python 3.13.5, окружения, FFmpeg, модели и VAD (обнаружение речи). Глобальные Python и Node.js для установки и обычной работы не нужны. Установщик не меняет NVIDIA-драйвер.

Выберите один способ получения файлов.

### Клонировать Git-репозиторий

Установите Git. В PowerShell выполните команды из родительской папки будущего проекта:

```powershell
Set-Location D:\
git clone https://github.com/DITEKmax/SLOI.git
Set-Location D:\SLOI
```

### Скачать ZIP с GitHub

Скачайте [архив ветки main](https://github.com/DITEKmax/SLOI/archive/refs/heads/main.zip) и сохраните его как `main.zip` в папке «Загрузки». В PowerShell распакуйте его в корень диска `D:`:

```powershell
Set-Location D:\
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\main.zip" -DestinationPath D:\
Set-Location D:\SLOI-main
```

Git для этого способа не нужен. Если архив распакован в другое место, укажите фактический путь в `Set-Location`.

### Установить зависимости

Команды запускайте в PowerShell из корня проекта. Для Git используйте `D:\SLOI`; для ZIP — `D:\SLOI-main`. Полный каталог должен находиться в доступной для записи папке.

```powershell
# Git:
Set-Location D:\SLOI
# ZIP вместо этой строки:
# Set-Location D:\SLOI-main
```

Перед установкой или повторной установкой остановите backend через `Ctrl+C`.

```powershell
.\install.bat
```

Установщик повторно использует подходящие локальные файлы и может продолжить прерванную загрузку. Для возобновляемых HTTP-загрузок можно вызвать установщик напрямую:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -RangeDownloads
```

`-SkipSmoke` пропускает проверку моделей на GPU и возвращает код 2. После него отдельно запустите короткую проверку из раздела «Проверка и отчёты».

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -SkipSmoke
```

| Код установки | Значение |
|---:|---|
| 0 | Среда подготовлена; короткие проверки инструментов и четырёх моделей прошли. |
| 2 | Среда подготовлена; GPU-проверка пропущена или завершилась не полностью. |
| 1 | Установка не завершена. Проверьте журнал и отчёты. |

Код 0 не измеряет точность на лекции и не обещает, что любая модель поместится в доступную видеопамять.

## Ежедневная работа

Запустите `start.bat` из корня проекта. Он откроет браузер на `http://127.0.0.1:8765`. Без автоматического открытия выполните в PowerShell из корня:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run.ps1 serve --no-browser
```

Уберите `--no-browser`, чтобы скрипт открыл браузер.

Backend продолжает очередь, если закрыть вкладку браузера. Окно процесса должно оставаться открытым. Нажмите `Ctrl+C` в этом окне, чтобы остановить приложение.

### Модель, язык и аудиодорожка

Выберите модель и язык для новых заданий до добавления файлов. Настройки темы, акцента, модели и языка сохраняются локально. Настройки ожидающего задания можно изменить в его строке очереди.

Язык `Авто` просит модель определить язык. GigaAM распознаёт только русский. Qwen принимает RU/EN как подсказку. Whisper здесь дообучен для русского; английский результат может быть хуже. Parakeet определяет язык самостоятельно и не получает RU/EN как параметр.

Для видео и контейнеров с несколькими дорожками приложение выбирает дорожку с отметкой «по умолчанию», иначе первую аудиодорожку. Перед запуском ожидающего задания можно выбрать другую дорожку. Дорожки не смешиваются.

### Добавить запись

Кнопка **«Добавить файлы»** и перетаскивание в браузер копируют данные в `runtime/uploads`. Браузерный путь допускает до 20 GiB на файл, до 40 GiB в кэше и оставляет 512 MiB свободного места на диске.

Для крупных записей раскройте **«Добавить без копирования»**. Кнопка **«Выбрать через Windows»** регистрирует исходный путь. **«Зона Windows для перетаскивания»** открывает отдельное системное окно. Эти способы читают исходник напрямую.

До конца браузерного переноса держите вкладку открытой. Отмена переноса удаляет незавершённую копию, но уже добавленные задания остаются в очереди. Успешная обработка освобождает временную копию, когда она больше не нужна. При ошибке или отмене копия сохраняется для повтора. Удаление последнего незавершённого задания освобождает её.

### Очередь и восстановление

Задания выполняются по порядку, по одному. Нажмите **«Пауза после текущей»**, чтобы дождаться окончания активного файла и остановить очередь. Пока файл обрабатывается, нажмите **«Продолжить очередь»**, если хотите снять паузу. Когда очередь уже остановилась, нажмите **«Запустить очередь»**.

**Внимание:** отмена останавливает только активное задание. Если очередь не поставлена на паузу, следующее ожидающее задание начнёт обрабатываться автоматически.

При отмене активного задания его обработка прекращается. При остановке приложения активное задание получает статус «Прервано». После запуска backend очередь сама не возобновляется. Нажмите **«Повторить»** у прерванного задания: обработка начнётся с начала файла.

Вкладку можно закрыть после завершения переноса. Backend продолжит очередь.

### Результаты

Готовые файлы лежат в `data/results/<идентификатор-задания>/`. Markdown содержит текст и YAML-метаданные: модель, язык, выбранную аудиодорожку, параметры обработки, время, телеметрию и предупреждения.

В интерфейсе доступны **«Открыть текст»**, **«Скачать Markdown»**, копирование текста и **«Папка результата»**. ZIP собирается из готовых Markdown-файлов. Удаление готового задания из списка не удаляет сохранённый результат.

## Проверка и отчёты

Запустите диагностику без распознавания из корня проекта:

```powershell
.\diagnose.bat
```

**Внимание:** перед `--smoke` остановите backend через `Ctrl+C`. Диагностика занимает блокировку каталога.

Для короткой GPU-проверки всех установленных моделей запустите из корня проекта:

```powershell
.\diagnose.bat --smoke
$LASTEXITCODE
```

Если в Windows нет синтезированного голоса для контрольного файла, укажите свою короткую запись:

```powershell
.\diagnose.bat --smoke --source "D:\Audio\short.wav"
$LASTEXITCODE
```

Код 0 означает, что короткая проверка прошла. Код 2 означает неполную проверку. Код 1 указывает на ошибку команды или окружения. Проверка не измеряет точность расшифровки.

**Внимание:** перед benchmark остановите backend через `Ctrl+C`. Команда занимает блокировку каталога, последовательно загружает модели и создаёт реальные расшифровки. Выберите короткую запись и только нужные модели:

```powershell
.\benchmark.bat "D:\Audio\short.wav" --language ru --models whisper qwen parakeet gigaam
```

Допустимые модели: `gigaam`, `qwen`, `whisper`, `parakeet`. Допустимые языки: `ru`, `en`, `auto`. Benchmark сохраняет отчёт в `data/reports/benchmark-<идентификатор>.json` и результаты в `data/results/`.

Установочные отчёты находятся в `data/reports/install.json`. Диагностика записывается в `data/reports/diagnostics.txt` и `data/reports/diagnostics.json`. Журнал первоначальной установки: `runtime/bootstrap/bootstrap.log`. Журнал приложения: `logs/app.log`.

Чтобы следить за концом журнала установки, откройте второе окно PowerShell в корне проекта:

```powershell
Get-Content .\runtime\bootstrap\bootstrap.log -Tail 20 -Wait
```

Нажмите `Ctrl+C`, чтобы остановить просмотр журнала.

## Локальные настройки

Базовые настройки находятся в [config/defaults.yaml](config/defaults.yaml). Локальный файл `config/app.yaml` перекрывает только указанные значения и не публикуется Git.

**Внимание:** если `config/app.yaml` уже существует, не заменяйте его примером. Добавьте нужные строки к существующим настройкам. Перед правкой остановите приложение через `Ctrl+C`.

Например, чтобы сменить занятый порт, добавьте этот частичный override:

```yaml
schema: 1
server:
  port: 8766
```

Сохраните файл, снова запустите `start.bat` и откройте `http://127.0.0.1:8766`.

Пользовательские настройки модели и интерфейса хранятся в `data/state.db` и имеют приоритет над их начальными значениями из YAML.

## Обновление Git-копии

ZIP-каталог не содержит Git-истории. Получите новую ZIP-версию целиком, если устанавливали приложение из ZIP.

Перед обновлением Git остановите приложение. Сохраните или зафиксируйте свои изменения. Выполняйте `git pull` только при чистом отслеживаемом рабочем дереве:

```powershell
Set-Location D:\SLOI
git status --short
git pull --ff-only origin main
```

Если `git status --short` показывает изменения, сначала сохраните их и очистите рабочее дерево. Игнорируемые `runtime`, `models`, `data`, `logs` и `config/app.yaml` остаются локальными при обычном fast-forward обновлении.

**Внимание:** остановите backend перед повторной установкой и короткой GPU-проверкой.

После изменения файлов в `requirements/` или `config/models.manifest.json` повторите установку и проверку:

```powershell
.\install.bat
.\diagnose.bat --smoke
```

## Если возникла ошибка

- **Установка завершилась кодом 1.** Откройте `runtime/bootstrap/bootstrap.log` и `data/reports/install.json`.
- **Установка вернула код 2.** Откройте `data/reports/diagnostics.txt`. Проверьте NVIDIA-драйвер и запустите `diagnose.bat --smoke` после устранения причины.
- **Занят порт 8765.** Задайте `server.port: 8766` в локальном `config/app.yaml` по примеру выше.
- **Модель не загружается или не хватает видеопамяти.** Закройте другие GPU-программы и повторите задание. Выберите другую модель, если ошибка сохраняется.
- **Исходник не найден после перемещения.** Выберите его снова через Windows или добавьте повторно.
- **Нужно проверить конкретную модель.** Прочитайте `data/reports/diagnostics.txt`; короткий smoke подтверждает запуск и непустой ответ, но не точность.

## Сборка и ограничения

В репозитории уже есть собранный интерфейс в `frontend/dist/`. Для обычной работы не нужен Node.js и не нужен dev-сервер.

Зафиксированная локальная проверка этой поставки: 71 тест прошёл, 1 был пропущен; четыре короткие GPU-проверки прошли 28 сентября 2026 года. Проверки интерфейса, API и Whisper CUDA прошли 3 октября 2026 года. Эти записи не подтверждают свежую установку на другом компьютере или качество длинной лекции.

Точная архитектура, ограничения памяти, безопасности и метрик описаны в [ARCHITECTURE.md](ARCHITECTURE.md). Тег поставки репозитория — `v2`; приложение пока сообщает внутреннюю версию `1.0.0-rc1`.
