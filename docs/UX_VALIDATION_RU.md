# SLOI — доработка интерфейса и проверка приложения

Дата: 2 октября 2026. Основа: приложенный архив `SLOI-main(1).zip`. Внешний GitHub main не использовался как подтверждённая актуальная версия: его содержимое в этой среде недоступно. Перед слиянием агент должен сравнить локальный код с исходными хешами в `delivery/changes.json`.

## Итоговый объём

По уточнению пользователя ошибка извлечения аудио из видео отсутствовала: была добавлена другая запись. Поэтому алгоритм декодирования аудио, VAD, сегментация, ASR-адаптеры, модели и их настройки не изменялись. Добавлены только описание и явный выбор аудиодорожки. PCM на реальном тестовом видео сверяется с исходной командой FFmpeg.

Главное изменение — прямое добавление аудио и видео в браузер перетаскиванием. Дополнительный выбор пути больше не нужен. За это удобство создаётся временная копия на диске; она удаляется после успешной расшифровки. Системный выбор Windows и отдельная Windows drop-зона сохранены для чтения крупных файлов по пути без копирования. Оба режима явно обозначены в интерфейсе.

## Путь пользователя

1. Выбрать модель и язык для новых записей в верхнем блоке. Параметры сохраняются между запусками. Если файлы уже добавлены, кнопка «Применить к ожидающим» меняет настройки всей остановленной очереди; активная обработка защищена от этой операции.
2. Перетащить одну или несколько записей в окно либо нажать «Добавить файлы». Для добавления по пути раскрыть «Добавить без копирования».
3. Дождаться переноса; проверить модель и язык в каждой строке. При нескольких аудиодорожках выбрать запись в очереди и нужную дорожку.
4. Нажать «Запустить очередь». При закрытой вкладке обработка уже добавленных файлов продолжается; незавершённый перенос требует открытой вкладки.
5. Следить за этапом, затем реальным процентом распознанной речи. Пауза означает остановку после текущей записи.
6. Выбрать любую запись независимо от текущей обработки. Открыть готовый текст, скопировать его или скачать Markdown/все результаты ZIP.
7. При ошибке прочитать причину и вернуть запись в очередь. При недоступном исходнике указать путь заново или добавить файл обычным способом.

## Движение и доступность

Сохранены три темы Carbon, Paper и Signal, их акценты и общий характер визуального поля. У поля появились разные частоты обновления: в ожидании задан интервал 125 мс, при обработке — 33,3 мс; фактическая частота зависит от браузера и нагрузки. В скрытой вкладке поле полностью прекращает планировать кадры. При reduced motion рисуется статическое состояние только при изменении данных. Координаты переиспользуются вместо создания тысяч новых объектов в каждом кадре.

Появление панелей занимает 180 мс; CSS-переходы отключаются при reduced motion. Процент и полоса по-прежнему отражают данные задачи, декоративное поле подписано отдельно. Диалоги используют HTML dialog: фокус ограничен окном, Escape закрывает его, после закрытия фокус возвращается к действию. Сохранён контраст текста при выборе слишком тёмного или светлого собственного акцента. Расшифровка выводится обычным текстом, без исполнения HTML из модели.

Это проверка поведения анимации, а не измерение энергопотребления/скорости ASR на ноутбуке пользователя. Сравнение скорости при открытой и закрытой вкладке ещё требует реального Windows/GPU запуска.

## Что исправлено в backend

- Потоковый приём браузерного файла с записями не более 1 МиБ за один вызов записи; нет чтения всего файла в память.
- Проверки типа, расширения, размера, свободного места, квоты и корректности медиа; локальные сессия, Origin и CSRF продолжают защищать новый маршрут.
- Очистка обрывов переноса и сирот при перезапуске. Копии после ошибок, отмены и прерывания сохраняются для повторного запуска; удаление задачи освобождает её копию. Оригинальные пользовательские файлы не удаляются.
- Сброс всех метрик старой попытки; атомарная замена идентичности и свойств исходника в SQLite; снятие зависшего cancelling после восстановления.
- Сохранение модели и языка новых файлов. Явный выбор дорожки до запуска, использование в обоих проходах и запись в метаданные результата.
- UTF-8 для русских имён в системном окне Windows, полный фильтр поддерживаемых форматов, понятные ошибки нативного процесса.
- Проверка пути результата внутри каталога своей задачи; недоступная телеметрия процесса не препятствует запуску приложения.

Лимиты временных файлов по умолчанию: 20 ГиБ на файл, 40 ГиБ суммарно, минимум 512 МиБ свободного места после записи. Они настраиваются в uploads через локальный config/app.yaml. Для файлов около 10 ГБ разумнее использовать режим без копирования, если свободного места мало.

## Проверки

- **72 pytest прошли**: HTTP/SQLite/реальный FFmpeg, выбор дорожек, очередь, сохранение/повтор/замена, локальная защита, большие sparse-файлы, процессы/IPC, загрузка и очистка копий. ASR-ответы заменены явно обозначенным тестовым адаптером.
- **Строгая сборка TypeScript и компиляция Vue-шаблона прошли**. Готовый frontend/dist поставляется в архиве; для обычного запуска Node.js не требуется.
- **Проверки жизненного цикла SignalField прошли**: активность, ожидание, reduced motion, скрытие вкладки, освобождение обработчиков и таймеров.
- **Chromium: 13 ширин × 3 темы (39 сочетаний)**: 320, 390, 699, 700, 768, 999, 1000, 1024, 1199, 1200, 1366, 1600 и 1920 px. Все без горизонтальной прокрутки. Проверены также ожидание, подготовка, VAD, ошибка, отмена, недоступный исходник, готовый текст и потеря связи. 27 проверок взаимодействий прошли.
- **91 проверка геометрии прошла**: блоки не пересекаются; элементы очереди остаются в своих строках; проверены также окно 1366×600 и семь состояний задач на семи ширинах. Кнопки действий на 320/390/699 px во всех темах имеют размер 44×44 px.
- **Живой браузерный сценарий: 12 проверок прошли** через настоящие HTTP/session/CSRF/WebSocket/API: перенос → WAITING → запуск → COMPLETE → просмотр/MD, применение настроек, пауза, отмена, закрытие вкладки во время обработки и восстановление результата.
- 62 снимка нового интерфейса, 39 снимков исходного, 7 снимков живого API и две GIF-записи поля. Снимки используют резервные шрифты; установленные Windows-шрифты не проверялись в этой среде. Данные тестовые, а не измерения NVIDIA GPU или реальное качество распознавания. Машиночитаемые результаты: validation/browser.json и validation/browser-live.json.

## Границы проверки

В этой среде не запускались реальные ASR-модели/CUDA на Windows, системные Windows-окна и чистая установка на ноутбук пользователя. Их нельзя считать проверенными по снимкам интерфейса. Для окончательной локальной приёмки: добавить реальные MP3/MP4 прямым перетаскиванием и по пути, проверить русское имя и файл большого размера, пройти распознавание, закрыть/открыть вкладку, проверить папку результата и очистку временного файла. Настоящий перезапуск backend, загрузка моделей и качество распознавания требуют проверки на целевой машине.

## Как применить

Внешний архив содержит полный проект SLOI/, изменённые файлы PATCH/ и delivery/changes.json с исходными и итоговыми SHA-256. Инструкция для локального агента: docs/MERGE_GUIDE_RU.md. При отличии локального файла от исходного хеша требуется обычное слияние кода. Не перезаписывайте пользовательский config/app.yaml, модели, виртуальные окружения, SQLite, результаты и журналы. Новые исполняемые зависимости не добавлены.
