# Добавление файлов: браузерная копия и исходный путь

## Поведение для пользователя

Перетаскивание файла в основную область и обычный браузерный выбор отправляют содержимое записи локальному серверу SLOI. Создаётся временная копия на диске в `runtime/uploads`. Копия нужна потому, что браузер не сообщает приложению абсолютный путь исходного файла. Файл передаётся частями: целиком в оперативную память запись не загружается. Исходник не изменяется.

Отдельное действие «Без копирования» использует системный выбор файлов Windows. В очередь записывается исходный путь; содержимое записи не передаётся и не дублируется. Этот режим подходит для особенно больших видео и ограниченного свободного места.

Когда браузерная загрузка завершена и файл прошёл проверку FFprobe, задача сразу появляется в очереди с выбранными моделью и языком. Отмена передачи удаляет частичную копию. При закрытии вкладки уже добавленная задача и её копия сохраняются: локальная обработка может продолжаться.

## Срок хранения копий

| Состояние | Что происходит с временной копией |
|---|---|
| Ожидание или обработка | Сохраняется для задачи |
| Готово | Удаляется, когда другие незавершённые задачи больше не используют этот исходник |
| Ошибка, отмена обработки, прерывание | Сохраняется для повтора; удаляется при удалении задачи |
| Удаление задачи | Удаляется, если других незавершённых задач с тем же исходником нет |
| Незавершённая передача или копия без задачи после перезапуска | Удаляется при запуске приложения |

Повторить успешно завершённую задачу с уже удалённой копией можно только после нового добавления исходника. Markdown-результаты и история сохраняются. Ошибочные и отменённые задачи намеренно сохраняют копии для повтора; чтобы освободить место, удалите ненужную задачу. Файлы, добавленные без копирования, SLOI не удаляет.

## Лимиты

По умолчанию: один файл до 20 GiB, все временные копии до 40 GiB, минимум 512 MiB свободного места на диске. Во время передачи свободное место и лимит копий проверяются повторно. Можно переопределить эти значения в `config/app.yaml`:

```yaml
uploads:
  max_file_bytes: 21474836480
  cache_quota_bytes: 42949672960
  min_free_bytes: 536870912
```

## API и проверка

`POST /api/files/upload?name=<URL-encoded filename>&model=whisper&language=ru` принимает один исходник как `application/octet-stream`. Нужны локальная сессионная cookie и заголовок `X-Sloi-Csrf`. Ответ: `{ok, job_id, source_id, source}`. Абсолютный путь сервер не возвращает. `GET /api/state` содержит `upload_limits`, а задача — `source_upload`.

Модель и язык проверяются до записи. Допускаются только поддерживаемые расширения и имя файла без путей. Проверка FFprobe выполняется до создания задачи. Недостаток места, неверный контейнер, обрыв и превышение размера не оставляют задачу или временный исходник. Содержимое кеша удаляется только для принадлежащих SLOI UUID-файлов; исходные пользовательские пути исключены.

`tests/test_uploads.py` проверяет передачу больше прежнего лимита HTTP-тела, сессию и CSRF, валидацию и очистку ошибок, лимиты диска, обрыв и отмену, повтор после перезапуска, совместные ссылки, удаление после успеха и защиту исходных файлов. Это проверка механизма ввода и жизненного цикла; качество моделей распознавания не меняется.
