# Фактическая архитектура 1.0.0-rc1

## Компоненты

`FastAPI + SQLite` — управление, очередь и состояние; `ModelManager` — один ASR subprocess; `FFmpeg/FFprobe` — только чтение медиа; `Silero ONNX CPU` — VAD; `Vue 3 + strict TypeScript` — SPA; `NVML/psutil` — мониторинг.

Frontend уже собран. Для обычного запуска нет Node.js/Vite dev server. Шаблон Vue предварительно компилируется в `render.js`, TypeScript — в `app.js`; runtime-компиляция и `eval` не требуются CSP. Сборка: `npm install` в frontend и `npm run build` (TypeScript 5.8.3). В облачной проверке использовался уже установленный `tsc`.

Источник истины для заданий — backend. API-команды меняют SQLite, WebSocket передаёт актуальные snapshots и telemetry. Переподключение не создаёт второе задание. Разрешён только loopback; Host/Origin, HttpOnly SameSite session, CSRF, ограничения размера запросов и типизированные payload дополняют отсутствие LAN-доступа. Это не система с несколькими пользователями и ролями.

## Файлы

Нативный picker или drop-регистрация выдаёт разрешённый source ID. Клиент не получает универсальный API чтения диска по пути. Регистрация читает метаданные и небольшой fingerprint: размер + первый/последний MiB. Это не полный криптографический идентификатор большого медиа. Полный SHA-256 считается в CLI benchmark.

Новый файл, брошенный на обычную браузерную страницу, не раскрывает путь: требуется подтверждение системным picker. Отдельное Windows drop-окно получает пути через WM_DROPFILES. Веб-страница не отправляет исходное содержимое на backend. Сетевые пути по умолчанию запрещены.

FFprobe определяет подходящую аудиодорожку и её индекс. Многодорожечное видео не смешивается автоматически; выбор отражается в предупреждениях MD. Проверяется наличие/размер/mtime исходника перед запуском и после обработки. Это защита от типовых изменений, а не доказательство неизменности каждого байта без полного хеша.

## Два прохода и ограниченная память

Первый проход FFmpeg выдаёт 16 kHz mono float PCM через pipe. Silero формирует speech regions, padded regions, общую длительность и компактную карту из 320 значений. Вся запись не хранится в RAM или WAV.

Второй проход FFmpeg последовательно подготавливает небольшую очередь фрагментов. Длина зависит от модели. Очередь ограничена, producer перекрывается с GPU inference. Передача в worker через shared memory ограничена размером batch; освобождение проверено IPC-тестом. Исходное медиа не копируется.

Это осознанный компромисс: два декодирования вместо огромного PCM-кэша, предсказуемая карта VAD и знаменатель progress. Единый VAD-pass действительно занимает время и включён в итоговую скорость. Он не является бесплатной стадией. VAD может ошибиться на очень тихой речи; предусмотрены padding и консервативный fallback для ненулевого сигнала, но абсолютной гарантии сохранения любой речи нет.

## Базовые модели/параметры

| ID | Runtime/env | Precision | Max fragment | Batch |
|---|---|---|---:|---:|
| gigaam | onnx-asr / onnx | FP32 | 22 s | 1 |
| qwen | Transformers / transformers | FP16, SDPA | 24 s | 1 |
| whisper | faster-whisper / whisper | INT8/FP16 | 28 s | 1 |
| parakeet | onnx-asr / onnx | FP32 | 12 s | 1 |

VAD threshold 0.35, negative 0.20, padding 400 ms, min silence 500 ms; overlap 350 ms. Это безопасные стартовые предложения, не параметры, уже оптимизированные на целевом ноутбуке.

ONNX preprocessing принудительно на CPU; основные сессии требуют CUDA. Включена проверка реального списка session providers, а не только установленного пакета. Допустимые CPU shape/служебные операции не означают переход всей ASR на CPU. Для ONNX arena задан лимит 3000 MiB, но это **не общий предел всех GPU-выделений** и не гарантия fit.

Qwen использует официальный Transformers-класс. Из ответа удаляется только служебный префикс языка/маркер, не переписываются повторы и запинки. Само поведение обученной ASR всё равно может нормализовать речь. Лимит генерации фиксируется как предупреждение при возможном обрыве. Whisper в этой версии обрабатывает фрагменты последовательно: изменение batch не превращает этот адаптер в BatchedInferencePipeline.

## Процессы и окружения

Небольшой core + отдельные onnx/transformers/whisper venv. Это не четыре одновременно загруженные модели: worker ровно один. Процесс с той же моделью переиспользуется между соседними заданиями. При смене, отмене и нездоровом runtime процесс завершается целиком; освобождение CUDA не сводится к `del model`.

На CUDA OOM происходит ограниченная серия повторов: worker перезапускается, batch делится или одиночный фрагмент уменьшается. Изменения не скрываются, отражаются в YAML. OOM уже на загрузке весов — отдельная ошибка, меньший фрагмент её не исправит. Способность библиотеки выбросить именно распознаваемый OOM на Windows ещё требует target smoke.

## Очередь и результаты

SQLite WAL/FULL, одна активная задача. Статусы: WAITING/PREPARING/ANALYSING/LOADING_MODEL/TRANSCRIBING/FINALIZING/COMPLETE, FAILED/CANCELLED/INTERRUPTED/SOURCE_MISSING. Ошибка одного задания не завершает диспетчер. Порядок не меняется ради группировки моделей. Автоматического запуска очереди после перезапуска нет.

Результат пишется атомарно: временный текст → fsync → replace. MD содержит данные источника без абсолютного пути, модель/revision/runtime, requested vs detected language, время, sampled telemetry, настройки, предупреждения. Тело — объединённый текст ASR. Overlap-дубликаты удаляются только при реально перекрывающихся фрагментах и совпадении минимум трёх слов; повторы вне границ не чистятся.

Временные данные принадлежат конкретному заданию. Нет постоянных WAV/chunks. MD остаются в `data/results` без автоматического удаления. Технические конфиги/БД/отчёты также занимают место — требование «только MD» относится к новым пользовательским медиа-артефактам, не к отсутствию файлов самого приложения.

## Честные проценты, скорость и ETA

Большой progress — сумма уникальных `owned` секунд успешно распознанных фрагментов / вся запланированная длительность после padding. Overlap не считается дважды. `detected_speech_seconds` и `planned_audio_seconds` — разные величины, они не подменяют друг друга.

До определения плана показывается стадия без выдуманного процента. При финализации допускается 100% ASR, но готовый результат появляется только после атомарного сохранения.

Live speed — покрытая позиция исходного timeline / elapsed, включая подготовку. На пропущенной длинной тишине она может изменяться скачком. Финальная `end_to_end_speed_x` — длительность источника / полное измеренное время обработки. В него входит VAD, загрузка, ASR и merge, но не ожидание в очереди и последний файловый write. Это точно указано в metadata, а не спрятано за словом realtime.

`asr_stage_speed_x` — длительность источника / время второго прохода, IPC и распознавания. `inference_calls_seconds` измеряется отдельно. **Speed x — обратная величина общепринятого RTF**, имена в коде не смешиваются.

ETA основан на последних 12 завершённых запросах и оставшихся planned seconds; до двух успешных единиц он отсутствует. Это оценка оставшегося ASR, не обещание точного времени finalization.

## Telemetry и анимация

Основной интервал 1 s. GPU/VRAM — показатели всего устройства, не только модели. RAM — системная; process-tree RSS может повторно считать общие страницы. Peaks — выборочные, краткий пик между измерениями может быть пропущен. Неподдерживаемая мощность/температура возвращается null, а не 0 или случайное число.

Canvas 2D: ограниченная сетка, 30 FPS, DPR до 1.5, выключение декора при скрытой вкладке; reduced motion сохраняет обновление данных без непрерывного движения. Canvas 2D **может аппаратно ускоряться браузером**. Поэтому утверждение «совсем не использует GPU» неверно; сравнение производительности ASR с открытым/закрытым UI ещё требуется на ноутбуке.

SVG/Canvas получают compact speech map/progress/telemetry, не сырые 90 минут PCM. Состояние визуализации не является дополнительной оценкой распознанных слов или модельного attention.

## Структура

```
sloi/                 backend, CLI, installer, updater
sloi/asr/             adapters, worker, manager
frontend/src/         Vue template, TS, CSS, Canvas
frontend/dist/        собранная SPA
config/               пользовательский override, defaults, pinned models
requirements/         основной набор pinned dependencies по env
scripts/              PowerShell/bootstrap/smoke/package
models/               создаётся установщиком
runtime/              Python, окружения, FFmpeg, кэш, temp
 data/                БД, результаты, отчёты, backups
logs/                 ротация
validation/           облачные отчёты и маркированные screenshots
```

## Принципиально не сделано

Нет LLM/облачного ASR, редактирования, записи микрофона, плеера, диаризации, перевода, полного resume внутри файла, автоматического выбора «лучшей» модели. Установка Windows, реальный CUDA inference и длинная лекция не подтверждены облачной средой.
